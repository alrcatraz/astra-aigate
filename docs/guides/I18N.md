# i18n — Internationalization Guide

## Scope

Astra AI Gate ships a **UI message catalog** (English + Chinese) and — previously — a
`docs/i18n/{locale}/` **documentation mirror tree**. The documentation mirrors and their
pipeline (`run-translation.mjs`, `sync-llm-mirrors.mjs`, `release:sync-changelog-i18n`,
`generate-multilang.mjs`) have been **removed**. Only the canonical English docs tree
under `docs/` is maintained.

The UI message catalog covers **43 locales** (British English base, zh-CN, zh-TW,
and 40 more), with `en.json` as the source of truth.

This guide covers the UI message catalog that remains.

## Source of Truth

- `config/i18n.json` — locale registry (codes, labels, direction).
- `src/i18n/messages/en.json` — canonical English strings (edit these).
- `src/i18n/messages/zh-CN.json`, `src/i18n/messages/zh-TW.json` — Chinese translations.

## Runtime Flow

`src/i18n/config.ts` is a thin typed adapter over `config/i18n.json`. Message files are
loaded at runtime by the i18n provider in `src/i18n/`; the app falls back to English for
any key missing from the active locale.

## Adding a New Language

1. Register the locale in `config/i18n.json`.
2. Add `src/i18n/messages/<code>.json` with translations for every key in `en.json`.
3. Run `npm run i18n:check-ui-coverage` (`scripts/i18n/check-ui-keys-coverage.mjs`)
   and `npm run i18n:check-value-drift` (`scripts/i18n/check-ui-value-drift.mjs`) — exit non-zero
   if any key is missing or stale (`__MISSING__:` markers force an English fallback, #7258).

## Pitfalls

- Never hand-edit locale lists in `src/i18n/config.ts` — the file is a thin adapter;
  edit `config/i18n.json` instead.
- Removing a UI feature: delete its keys from **all three** message files in the same
  change, or `check-ui-value-drift.mjs` flags the orphans.
